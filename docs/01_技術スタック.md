# ManaBloom 技術スタック

## 1. 文書情報

- 対象バージョン: 0.1.0
- 作成日: 2026-08-12
- 対象: 初期リリース版（端末内保存・課金なし）

## 2. システム概要

ManaBloomは、ユーザー自身が問題を作成して反復学習するレスポンシブPWA兼iOSアプリである。Webブラウザ版とCapacitorで包装したiOS版を一つのReactコードベースから生成し、ログインやサーバーDBを使用せず、問題・回答履歴・設定を利用端末内に保存する。

## 4. 現在使用していない技術

- C# / ASP.NET Core: 現時点ではサーバーAPIがないため未使用。
- PostgreSQL: データを端末内に保存するため未使用。
- Flutter: PWAとして提供するため未使用。
- 認証基盤: ログイン機能がないため未使用。
- 課金基盤: 初期リリースでは未導入とし、課金に関するUIも表示しない。

## 5. 技術選定理由

- ReactとTypeScriptにより、既存スキルを活用しつつスマホ・PC共通のUIを一つのコードベースで提供できる。
- PWAとCapacitorにより、Flutterなどの大容量SDKを追加せず、Web版とApp Store向けiOS版を共通実装で提供できる。
- IndexedDBとDexieにより、DBサーバーや月額費用なしで構造化データを永続化できる。
- JSONバックアップにより、サーバーなしでもデータ保全と別端末への手動移行ができる。

## 6. 制約

- データは自動同期されず、ブラウザ・端末・オリジンごとに独立する。
- サイトデータ削除やアプリデータ消去によりデータが失われる可能性がある。
- 端末移行にはJSONバックアップの書き出しと読み込みが必要である。
- Web版の初回アクセスとPWAインストールにはオンライン接続が必要である。iOSアプリ版は資材を内包するため初回からオフライン起動できる。
- App Store公開前にMac/Xcodeで署名し、iPhone実機とTestFlightで確認する。

## 7. 将来拡張

ログイン、自動同期、共有、課金を導入する場合は、C# / ASP.NET Core APIとPostgreSQLを追加する。端末内DBはオフラインキャッシュとして残し、同期APIとの競合解決、ユーザー所有権、認証・認可を新たに設計する。
