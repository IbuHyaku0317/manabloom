# ManaBloom テスト設計書

## 1. 目的

初期リリース版の主要機能、端末内保存、オフライン利用、スマホ表示、バックアップ移行が要件どおり動作し、学習データを損なわないことを確認する。

## 2. テストレベル

| レベル | 内容 | 実施方法 |
|---|---|---|
| 静的検査 | 型、安全でない記述、アクセシビリティ規則 | `tsc --noEmit`、ESLint |
| ビルドテスト | 全環境向け成果物の生成 | `npm run build` |
| 自動基本テスト | WorkerがHTMLを正常応答すること | Node.js Test Runner |
| 機能テスト | 問題CRUD、回答、履歴、設定、バックアップ | ブラウザ手動テスト。順次自動化 |
| 互換性テスト | PC、Android、iOS | 実機または端末ブラウザ |
| オフラインテスト | キャッシュと端末内DB | PWAインストール後の機内モード |

## 3. 対象環境

| 区分 | 対象 |
|---|---|
| PC | 最新版Chrome、Edge |
| Android | 最新版Chrome、ホーム画面追加状態 |
| iPhone | 最新版iOS Safari、ホーム画面追加状態 |
| 画面幅 | 320px、375px、768px、1280px以上 |
| 通信 | オンライン、低速、オフライン |

## 4. 合否基準

- 重大度CriticalまたはHighの不具合が0件であること。
- ビルド、型検査、Lint、自動テストがすべて成功すること。
- データ保存・復元・削除で意図しないデータ欠損がないこと。
- AndroidおよびiPhoneで主要学習フローを完了できること。
- オフライン再起動後に問題と履歴が保持されること。

## 7. 非機能テスト

- 主要画面が320px幅で横スクロールしない。
- タップ対象が隣接要素と誤操作しにくい大きさである。
- 問題500件、回答履歴10,000件を登録して主要画面が実用時間内に表示される。
- バックアップに問題文・答えが正しくUTF-8で保存される。
- 画面表示、Manifest、タイトル、テスト名に文字化けがない。
- 課金、数式、画像添付など、初期リリースで提供しない機能が画面に表示されない。

## 8. 現状と追加自動化方針

現状の自動テストは、ビルド成果物がHTMLを200で返す基本確認が中心である。正式公開前に、問題CRUD、正誤判定、時間切れ、IndexedDB再起動保持、バックアップ検証・復元をブラウザE2Eテストとして追加することを推奨する。
